# 다왔어 디자인 명세

> 화면별로 어떤 디자인이 필요한지 정리한 요구사항 문서다.
> 시각적 결정(색, 폰트, 간격, 모양)은 포함하지 않는다. 새 디자인은 이 문서의 요구사항을 모두 충족해야 한다.
> 현재 코드는 디자인 요소를 모두 제거한 상태이며 Material 3 기본값으로 렌더링된다.

작성일: 2026-11-18

---

## 0. 전체 구조와 공통 요구사항

### 0.1 화면 흐름

```text
Splash
 ├─ (세션 없음) → Login ─ Sign up
 └─ (세션 있음) → Main (하단 탭 4개)
                   ├─ Home (지도)
                   │    ├─ 장소 검색 바텀시트
                   │    └─ 알람 설정 바텀시트
                   ├─ Alarms (알람 목록)
                   │    ├─ 알람 삭제 확인 다이얼로그
                   │    └─ Sound list (별도 route, 탭바 없음)
                   │         └─ 녹음 바텀시트
                   ├─ Friends (친구)
                   │    ├─ 친구 검색 바텀시트
                   │    ├─ 알람 보내기 바텀시트 (알람 설정 시트 재사용)
                   │    └─ 삭제/차단 확인 다이얼로그
                   └─ Profile
Alarm ringing (별도 Activity, 잠금화면 위에 표시)
시스템 알림 2종 (위치 추적 중, 도착 알람)
```

구현 위치: `navigation/WakepointNavGraph.kt`, `feature/*`, `feature/alarmalert/AlarmAlertActivity.kt`

### 0.2 공통 컴포넌트 (API는 유지됨, 스타일만 비어 있음)

`core/design/Component.kt`, `core/design/RadiusSelector.kt`에 아래 컴포넌트가 있다. 새 디자인은 이 API 위에 스타일을 입히거나 API를 바꾸되, 사용처를 함께 수정해야 한다.

| 컴포넌트 | 역할 | 사용처 |
|---|---|---|
| `WakepointButton` | Primary 액션 버튼. 텍스트, 선택적 아이콘, enabled 상태 | 로그인, 회원가입, 알람 추가/저장, 검색, 친구 수락, 알람 중지 등 |
| `WakepointSecondaryButton` | 보조 액션 버튼. 취소, 삭제, 거절, 차단, 가져오기 | 바텀시트 하단, 카드 액션 |
| `WakepointTextField` | 단일행 입력. placeholder, leading/trailing 아이콘, readOnly, 비밀번호 | 로그인, 회원가입, 별칭, 검색 |
| `WakepointCard` | 목록 아이템 컨테이너 | 알람 카드, 친구 카드, 빈 상태 카드, 사운드 목록 |
| `WakepointConfirmDialog` | 제목, 메시지, 취소/확인 버튼 2개 | 알람 삭제, 친구 삭제, 친구 차단 |
| `WakepointHeader` | 화면 상단 헤더. 좌측 브랜드, 우측 액션 슬롯 | 알람, 친구, 프로필 탭 |
| `StatusPill` | 상태 라벨 (텍스트 + 상태 색) | 친구 상태, 권한 상태 |
| `SoundOptionRow` | 아이콘 + 제목 + 부제 + trailing 슬롯, 클릭 가능 | 알람음 선택 행 |
| `BottomSheetHandle` | 바텀시트 드래그 핸들 | 모든 ModalBottomSheet |
| `RadiusSelector` | 반경 옵션 드롭다운 (100m ~ 50km) | 알람 설정 시트, 알람 수정 카드 |
| `WakepointTheme` | MaterialTheme 래퍼. 색/타이포/모양 토큰 주입 지점 | MainActivity, AlarmAlertActivity |

### 0.3 공통 상태 표현

모든 화면에서 아래 상태를 시각적으로 구분해야 한다.

- 로딩/제출 중: 버튼 텍스트가 "처리 중", "저장 중", "검색 중"으로 바뀌고 비활성화된다. 스피너는 현재 없다.
- 오류 메시지: 폼 아래 또는 목록 상단에 한 줄 텍스트로 표시된다. 오류와 안내 메시지의 구분이 필요하다.
- 안내 메시지: 알림 권한 미허용 안내, 이메일 확인 안내 등.
- 빈 상태: 알람 없음, 친구 없음. 친구 빈 상태에는 CTA 버튼이 있다.
- 비활성 항목: 비활성 알람은 활성 알람과 구분되어야 한다.
- 개별 항목 갱신 중: 카드 단위로 스위치/버튼이 비활성화된다 (`isUpdating`).

### 0.4 플랫폼 제약

- Edge-to-edge가 켜져 있다. 상태바/네비게이션바 영역 처리가 필요하다.
- 알람 울림 화면은 잠금화면 위에 뜨고 화면을 켠다. 잠금 상태에서도 즉시 읽히고 가장 큰 버튼 하나로 중지할 수 있어야 한다.
- 카카오 로그인 버튼은 카카오 공식 이미지 에셋을 사용한다. 카카오 디자인 가이드를 따라야 하므로 자유 디자인 대상이 아니다.
- 바텀시트는 Material 3 `ModalBottomSheet`를 사용하고 `skipPartiallyExpanded = true`다.
- 지도는 Google Maps SDK이며 마커 아이콘은 현재 기본 마커다. 커스텀 마커 비트맵이 필요하면 drawable로 제공해야 한다.
- 하단 탭바는 Material 3 `NavigationBar`다.

### 0.5 브랜드 자산 (현재 없음, 새로 필요)

- 앱 아이콘 (adaptive icon). 현재는 임시 벡터 `ic_launcher.xml`을 쓴다.
- 로고 (가로형, 정사각형). 스플래시, 로그인, 헤더, 알람 울림 화면에서 쓴다. 현재는 앱 이름 텍스트로 대체돼 있다.
- 지도 목적지 마커 아이콘.
- 기본 폰트. 현재는 시스템 기본 폰트다.
- 컬러 팔레트와 다크 모드 여부. 현재 다크 모드 대응은 없다.
- 알림 아이콘 (상태바용 단색 small icon). 현재 시스템 기본 아이콘을 쓴다.

## 2. 로그인 (Auth)

구현: `feature/auth/AuthScreen.kt` `AuthScreen`

**목적**: 이메일 로그인 또는 카카오 로그인.

**요소**
- 상단 바 (뒤로가기 아이콘만 있고 현재 동작 없음. 제거 또는 용도 결정 필요)
- 로고 (세로형)
- 소개 문구 (`auth_intro`)
- 이메일 입력, 비밀번호 입력 (마스킹)
- 메시지 영역: 오류 또는 안내 (`errorMessage` / `infoMessage`)
- 로그인 버튼 (제출 중이면 "처리 중" + 비활성)
- 카카오 로그인 버튼 (공식 이미지, 제출 중이면 반투명 + 비활성)
- 하단 텍스트 링크: "비밀번호 찾기" | "회원가입" (비밀번호 찾기는 동작 없음)
- 약관 안내 문구, 저작권 문구 (최하단)

**상태**: 기본 / 제출 중 / 오류 / 안내.

**디자인 결정 필요**: 이메일 폼과 소셜 로그인의 우선순위 배치, 오류 메시지 위치와 색, 키보드가 올라왔을 때의 레이아웃(현재 스크롤 없음).

## 3. 회원가입 (Sign up)

구현: `feature/auth/AuthScreen.kt` `SignUpScreen`

**목적**: 이름, 이메일, 비밀번호, 비밀번호 확인으로 가입.

**요소**
- 상단 바: 뒤로가기 + 제목 (`signup_title`)
- 라벨이 있는 입력 필드 4개 (이름, 이메일, 비밀번호, 비밀번호 확인). 각 필드에 라벨과 힌트가 있다.
- 메시지 영역 (오류/안내)
- 회원가입 버튼 (제출 중이면 "처리 중")
- 세로 스크롤 가능

**상태**: 기본 / 제출 중 / 오류 / 안내 (이메일 확인 메일 발송 안내 포함).

**디자인 결정 필요**: 필드 라벨 스타일, 필드별 인라인 오류 표시 여부 (현재는 폼 전체에 메시지 하나), 전화번호 필드는 MVP에서 제외됨.

## 4. 홈 (지도)

구현: `feature/home/HomeScreen.kt`

**목적**: 지도에서 목적지를 고르고 알람을 만든다. 앱의 중심 화면.

### 4.1 지도 화면

**요소**
- 전체 화면 Google Map. 내 위치 표시(권한 있을 때), 컴퍼스/줌 컨트롤/지도 툴바 모두 꺼져 있음.
- 선택된 목적지 마커 1개 (지도 탭 또는 검색 결과 선택으로 이동)
- 상단 오버레이: 검색바 (클릭 시 검색 시트, 우측 마이크 아이콘으로 음성 검색)
- 우하단 FAB: 현재 위치로 이동 (권한 없으면 권한 요청)
- 하단 Primary 버튼: "알람 만들기" (하단 탭바 위에 고정, 전체 폭)

**상태**
- 위치 권한 없음: 지도 기본 위치(서울시청). FAB 클릭 시 권한 요청.
- 위치 권한 있음: 현재 위치로 카메라 이동, 목적지 기본값이 현재 위치.
- 알림 권한 없음 (Android 13+): 알람 만들기 버튼 클릭 시 권한 요청, 시트 안에 안내 문구.

**디자인 결정 필요**: 지도 위 오버레이 요소의 대비와 그림자, 마커 아이콘, 검색바와 FAB와 하단 버튼이 지도를 가리는 정도, 반경 원 표시 여부(현재 없음).

### 4.2 장소 검색 바텀시트

**요소**
- 제목 (`place_search_title`)
- 검색 입력 (leading 검색 아이콘, trailing 마이크 아이콘)
- 검색 버튼 (검색 중이면 "검색 중" + 비활성)
- 오류 메시지 (선택)
- 결과 목록: 행마다 위치 아이콘 + 장소명 + 주소. 클릭 시 선택 후 시트 닫힘.

**상태**: 입력 전 / 검색 중 / 결과 없음(메시지) / 결과 있음 / 오류.

**디자인 결정 필요**: 결과 행 디자인, 결과가 많을 때 스크롤 (현재 Column, LazyColumn 아님), 키보드와 시트 높이 관계.

### 4.3 알람 설정 바텀시트

구현: `AlarmSetupSheet` (홈과 친구 화면에서 공용)

**요소**
- 제목 ("알람 설정" 또는 "알람 보내기")
- (친구 화면에서만) 주소 검색 입력 (현재 동작 없음)
- 섹션 라벨 + 위치 별칭 입력
- 섹션 라벨 + 선택된 목적지 (읽기 전용, 주소 텍스트)
- 섹션 라벨 + 반경 선택 드롭다운
- 섹션 라벨 + 알람음 행 (기본 알람음, chevron. 홈에서는 동작 없음)
- 안내 문구 (알림 권한 없을 때)
- 버튼 2개 가로: 취소(보조) / 추가 또는 보내기(Primary). 저장 중이면 "저장 중" + 비활성.
- 오류 메시지 (버튼 아래)

**디자인 결정 필요**: 섹션 라벨과 필드의 묶음 간격, 읽기 전용 필드의 표현, 시트가 길어질 때 스크롤.

## 5. 알람 목록 (Alarms)

구현: `feature/alarms/AlarmsScreen.kt`

**목적**: 내 알람을 활성/비활성으로 나눠 보고 토글, 수정, 삭제한다.

**요소**
- 헤더 (브랜드 + 우측 "+" 액션 → 홈으로 이동)
- 오류 메시지 (선택)
- 빈 상태 카드 (`alarm_empty`)
- 섹션 제목 "활성 알람" / "비활성 알람"
- 알람 카드 (접힘/펼침 두 가지)
- 삭제 확인 다이얼로그

### 5.1 알람 카드 (접힘)

- 1행: "위치: {별칭}"
- 2행: 목적지 주소 (제목급)
- 3행: "반경 {500m|2km}"
- 우측: 활성 스위치 (갱신 중이면 비활성)
- 카드 클릭 시 펼침
- 비활성 알람은 텍스트가 흐려짐

### 5.2 알람 카드 (펼침)

- 1행: "위치: {별칭}" + chevron + 스위치 (행 클릭 시 접힘)
- 섹션 라벨 + 별칭 입력
- 섹션 라벨 + 반경 드롭다운
- 섹션 라벨 + 알람음 행 (클릭 시 사운드 목록 화면)
- 버튼 2개 가로: 저장(Primary) / 삭제(보조)

**디자인 결정 필요**: 접힘/펼침 전환 애니메이션, 활성/비활성 구분 방식, 카드 안의 폼이 너무 길어지는 문제 (별도 수정 화면으로 뺄지), 생성자(created_by)가 친구일 때의 표시 (현재 없음, 대리 알람 기능 시 필요).

## 6. 알람음 목록 (Sound list)

구현: `feature/alarms/AlarmsScreen.kt` `SoundListScreen`, `RecordingSheet`

**현재 상태**: UI 목업이다. 선택, 가져오기, 녹음 모두 동작하지 않는다.

**요소**
- 상단 바: 뒤로가기 + 제목 (`alarm_sound_list_title`)
- 사운드 목록 카드: 행마다 아이콘 + 제목 + 부제 + (선택됨이면 체크 아이콘). 행 사이 구분선. 4개 샘플.
- 하단 고정 버튼 2개: 가져오기(보조, 다운로드 아이콘) / 녹음(Primary, 마이크 아이콘)
- 녹음 바텀시트: 제목, 경과 시간 (큰 숫자), 정지 버튼 (아이콘), 구분선, 취소/저장 버튼

**디자인 결정 필요**: 선택 상태 표현, 재생 미리듣기 버튼 (현재 없음), 녹음 중 파형이나 레벨 미터 여부, 커스텀 사운드 항목의 삭제 UX.

## 7. 친구 (Friends)

구현: `feature/friends/FriendsScreen.kt`

**목적**: 친구 관계, 친구 요청, 알람 대리 설정 권한 요청을 관리하고 권한 있는 친구에게 알람을 보낸다.

**요소**
- 헤더 (브랜드 + 우측 액션 2개: 새로고침, 친구 추가)
- 검색바 (읽기 전용, 클릭 시 검색 시트)
- 오류 메시지 (선택)
- 빈 상태 카드: 안내 2줄 + "친구 검색" 버튼
- 섹션 5개 (내용이 있을 때만 표시, 이 순서)
  1. 받은 친구 요청
  2. 보낸 친구 요청
  3. 받은 알람 권한 요청
  4. 보낸 알람 권한 요청
  5. 친구
- 우하단 확장 FAB: 아이콘 + "친구 추가"
- 친구 검색 바텀시트
- 알람 보내기 바텀시트 (4.3 재사용, 현재 저장 동작 없음)
- 삭제/차단 확인 다이얼로그

### 7.1 친구 요청 카드

- 아바타 (이니셜 또는 이미지) + 닉네임 + 이메일 + 상태 pill ("요청 받음"/"요청 중")
- 받은 요청: 수락(Primary) / 거절(보조) 가로 2개
- 보낸 요청: 요청 취소(보조) 전체 폭

### 7.2 알람 권한 요청 카드

- 아바타 + 닉네임 + 설명 한 줄 ("내 알람을 대신 설정할 권한 요청" / "상대방 알람 설정 권한 요청 중") + "만료 없음" + 상태 pill (권한 없음/대기/승인/거절)
- 받은 요청만 수락/거절 버튼

### 7.3 친구 카드

- 접힘: 아바타 + 닉네임 + 이메일 + 권한 상태 한 줄 ("알람 권한 없음/요청 중/있음/거절됨") + 친구 상태 pill
- 펼침 (클릭): 구분선 아래 버튼 3개 가로 (알람 보내기 Primary / 차단 보조 / 삭제 보조) + 전체 폭 권한 버튼 ("권한 요청"/"권한 대기"/"권한 있음", 요청 가능할 때만 활성)
- 알람 보내기는 친구 수락 + 권한 승인 상태에서만 활성

### 7.4 친구 검색 바텀시트

- 제목 "친구 검색"
- 가로: 검색 입력 (weight) + 검색 버튼 (고정 폭)
- 안내/오류 메시지 (2자 미만, 결과 없음 등)
- 결과 행: 아바타 + 닉네임 + 이메일 + (이미 친구면 상태 pill, 아니면 "요청" 버튼). 행 클릭으로 선택하면 강조되고 그때만 요청 버튼 활성.

**상태 색이 필요한 값**
- 친구 상태: 친구 / 요청 중 / 요청 받음 / 거절됨 / 차단됨
- 권한 상태: 권한 없음 / 대기 / 승인 / 거절

**디자인 결정 필요**: 섹션 5개가 한 화면에 쌓이는 정보 구조 (탭이나 필터로 분리할지), 상태 pill 색 체계 (현재 5+4개 상태에 색 4종), 아바타 placeholder, 카드 펼침 시 버튼 3개가 좁은 화면에서 깨지는 문제, FAB와 헤더 액션의 중복.

**개인정보 제약**: 요청자에게 상대의 위치, 도착, 알람 울림 상태를 보여주는 어떤 UI도 만들면 안 된다. `docs/DESTINATION_ALARM_PRIVACY.md` 참조.

## 9. 알람 울림 (Alarm ringing)

구현: `feature/alarmalert/AlarmAlertActivity.kt`

**목적**: 목적지 반경 진입 시 잠금화면 위에 떠서 알람을 중지시킨다. 앱에서 가장 중요한 단일 화면.

**요소**
- 중앙 카드: 로고 + "도착했습니다" 제목 + 장소 별칭 + 목적지 주소(별칭과 다를 때만) + "알람 중지" Primary 버튼 (전체 폭)

**제약**
- 잠금 상태, 어두운 환경, 이동 중에 한 손으로 즉시 누를 수 있어야 한다.
- 소리와 진동이 울리는 중이다. 중지 버튼 외의 요소는 최소화한다.
- 이 Activity는 자체 `WakepointTheme`을 감싼다. 메인 앱과 같은 테마를 써야 한다.

**디자인 결정 필요**: 전체 화면 배경, 버튼 크기 (일반 버튼보다 커야 함), 스누즈 여부 (현재 없음), 지도 미리보기 여부.

## 12. 디자인 적용 전 선행 정리 항목

- 친구 화면에 한글 문자열 약 40곳이 코드에 직접 들어 있다 (섹션 제목, 버튼, 상태 텍스트, 다이얼로그). `strings.xml`로 옮긴 뒤 디자인을 입히는 편이 안전하다.
- 홈 화면 `"검색 결과"` fallback 문자열도 코드에 있다.
- 프로필 이름은 고정 문자열이다. 디자인 전에 실제 데이터 연결이 필요하면 ViewModel을 추가해야 한다.
- 사운드 목록은 목업이다. 디자인은 할 수 있으나 데이터 모델(`SoundType`, `soundUri`)과 연결하는 작업이 별도로 필요하다.
- 로그인 화면 상단 바의 뒤로가기 버튼은 동작이 없다. 제거하거나 용도를 정한다.

## 13. 디자인 적용 시 권장 순서

1. `core/design/Theme.kt`에 색상, 타이포, 모양 토큰을 정의하고 `WakepointTheme`에 주입한다.
2. `core/design/Component.kt`의 공통 컴포넌트에 스타일을 입힌다. 이 단계만으로 대부분의 화면이 바뀐다.
3. 브랜드 자산(앱 아이콘, 로고, 마커, 알림 아이콘, 폰트)을 `res/`에 추가하고 헤더/스플래시/알람 울림 화면에 연결한다.
4. 화면별 레이아웃을 손본다. 우선순위: 알람 울림 → 홈 → 알람 목록 → 친구 → 로그인/회원가입 → 프로필 → 사운드 목록.
5. 하단 탭바와 바텀시트 컨테이너 스타일을 맞춘다.
6. `docs/DESIGN.md`에 확정된 토큰과 규칙을 기록하고 `AGENTS.md` 디자인 규칙을 갱신한다.
