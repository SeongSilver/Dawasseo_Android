## 원격 연동 판단 (계획서 "가능분 식별" 결과)
| 항목 | 판단 | 근거 |
|---|---|---|
| 보낸 알람 목록/취소 | ✅ 실기능 | 기존 `alarms` 테이블에 `created_by` 존재 — 추가 스키마 불필요 |
| 수신 감지 다이얼로그 | ✅ 실기능 | refreshAlarms 병합 결과에서 로컬 감지 — 서버 변경 불필요 |
| 친구 공개 장소(장소 탭) | ❌ 빈 상태 | 공개 장소 테이블/동기화 없음(내 장소는 로컬 전용) → 빈 상태(3c)가 사실 |
| 시간 알람 전송(시간 탭) | ❌ UI만 | 원격 time_alarms 스키마·FCM 페이로드 없음 → 보내기 차단+안내(3-5) |
| 수신자 버전 가드(3-5) | 부분 | 서버에 앱 버전 필드 없음 → '서버 업데이트 필요' 안내로 대체 |

## 설계 결정
- 수신 감지를 푸시가 아닌 **풀 기반**으로: FCM 페이로드/서버 함수 수정 권한이 없어도
  동기화만 되면 다이얼로그가 뜨고, 푸시 유실에도 안전하다.
- 보낸 알람 상태는 **전송 대기/전송됨 2단계**: 데모의 "기기 등록됨"은 서버에 등록 ACK
  신호가 없어 판별 불가 → 판별 가능한 사실만 표시.
- 확인(acknowledged) 상태는 기기 로컬 prefs(`wakepoint_received_alarms`) — 서버 스키마 불변.
