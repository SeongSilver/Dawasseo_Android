# v2 재구축 계획 — 명세 기반 정석 재구현

> 결정: 기존 `feature/v2/**` 데모 코드를 **전부 제거하고**, 디자인 명세대로 실화면을
> **백엔드 포함** 처음부터 재구축한다. (사용자 지시, 2026-08-10)
> 소스 명세: `design/v2-spec.dc.html`(= 공유 프로젝트 `v2 통합 명세.dc.html`, 동일본) +
> 화면별 상세(`v2 시간/내장소/친구/막차 화면.dc.html`).

## 0. 왜 재구축인가 (현 상태 진단)
- 기존 v2는 **네비에 연결되지 않은 고립 데모 Composable**로 만들어져 앱에서 열리지 않음
  → v2 디자인이 실제 앱에 **반영되지 않음**(확인 완료).
- v2 데모는 상호작용 배선(콜백/상태)이 없어 실기능화가 불가.
- 따라서 데모를 걷어내고 **도메인·영속성·스케줄링 → UI → 네비 → 테스트** 순으로 재구축.

## 1. 인프라 실사 결과 (재사용 가능 자산)
| 인프라 | 상태 | 재구축 활용 |
|---|---|---|
| Room 로컬 DB (`WakepointDatabase`, Alarm/Friend Dao·Entity) | ✅ | 시간알람 필드·Place 테이블 추가 |
| Supabase 원격 | ✅(설정 존재) | 신규 테이블은 **DB 접근 권한 확보 시** 동기화, 없으면 로컬 우선 |
| FCM 푸시 (`WakepointFirebaseMessagingService`) | ✅ | 친구 알람 송수신 재사용 |
| 위치추적(지오펜스) | ✅ | 위치 알람 |
| **AlarmManager 시간 스케줄링** | ❌ 없음 | **신규 구축**(시간알람의 핵심) |
| **Kakao 경로/모빌리티(대중교통 막차)** | ❌ 없음 | **외부 API+키 미확보 → 막차 실기능 불가** |

## 2. 화면 인벤토리 (명세 30화면 / STEP4)
- **STEP1 시간알람**: 1-1 타입선택 · 1-2 생성(+요일직접/오류) · 1-3 목록 · 1-4 편집 · 1-5 권한 · 1-6 정확도배지
- **STEP2 내장소**: 2-1 목록(+마이 진입점) · 2-2 등록·편집 · 2-3 공개 ON/OFF · 2-4 삭제
- **STEP3 친구알람**: 3-1 목록 · 3-2 주소 · 3-3 장소(+빈상태) · 3-4 시간 · 3-5 버전가드 · 3-6 보낸알람 · 3-7 수신
- **STEP4 막차**: 4-1 여유/임박/아슬 · 4-2 끊김 · 4-3 집미등록 · 4-4 미지원 · 4-5 위치동의 · 4-6 보내기/수신

## 3. 단계별 로드맵 (각 단계: 빌드+유닛테스트 그린 유지, 항목 단위 커밋)

### Phase 1 — 클린 슬레이트 ⬅ 지금
- `feature/v2/**`(18파일) 및 데모 대상 테스트(`TimeAlarmLogicTest`/`V2ModelsTest`/`V2ScreenE2ETest`) 제거.
- **유지**: 디자인 토큰(`core/design/ColorV2·SizeV2·TypeV2`) — v2 SSOT 확장, 재구축에 그대로 사용.
  버그수정(알람 시트 스크롤), 친구 보내기 3탭(기능 정상)은 유지.

### Phase 2 — 시간 알람 (STEP1) · 로컬 완결 가능
- 도메인: `AlarmType{LOCATION,TIME}` 도입 또는 `TimeAlarm` 신규 + 반복(RepeatMode)·요일.
- Room: 스키마 확장 + 마이그레이션. 스케줄링: `AlarmManager.setExactAndAllowWhileIdle` +
  수신 `BroadcastReceiver` + 재부팅 복원(`BootCompletedReceiver` 확장).
- UI: 1-1~1-6 명세대로 구현 → **알람 탭 네비 배선**.
- 테스트: 다음 발화 시각·반복 전개·요일 계산 순수함수 유닛테스트(TDD).

### Phase 3 — 내 장소 (STEP2) · 로컬 완결 가능
- 도메인 `Place`(내이름/공유이름/공개/주소비공개/집 고정) + Room `PlaceDao/Entity`.
- UI: 2-1~2-4 + 마이(Profile) 진입점 배선. 테스트: 공개/이름 규칙.

### Phase 4 — 친구 알람 (STEP3) · 부분 원격
- `FriendsViewModel` 확장: 보내기 3탭(주소=기존 실기능 / 장소=Place 연동 / 시간=시간알람 연동),
  보낸알람 목록·수신. 원격(Supabase/FCM) 스키마 필요분 식별 → 가능분 연동, 불가분 로컬.

### Phase 5 — 막차 (STEP4) · 외부 의존 (제약)
- Kakao Mobility(대중교통 경로/막차시각) **미확보** → **UI만 명세대로 구현 + 계산은 모의/스텁**.
  실기능은 API 키·백엔드 확보 후 별도. 3단계 임계값(여유/임박/아슬 분)은 제품 확정 필요.

### Phase 6 — v1.5 정합/마감
- 명세대로 기존 탭 최종 정리, 문서 갱신, 통합 회귀 점검.

## 4. 교차 제약 (반드시 인지)
- **디바이스 없음** → UI는 컴파일+유닛테스트로만 검증. 계측(E2E)은 코드 작성만, 실행은 기기 필요.
- **Supabase 신규 테이블/서버 함수** 프로비저닝 권한 없으면 원격 동기화 보류(로컬 우선).
- **막차 실기능**은 외부 모빌리티 API 없이는 불가 — UI/모의까지만.
- 규모상 **여러 세션**에 걸침. 단계별로 그린 유지하며 점진 머지.
